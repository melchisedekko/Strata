## Problem and result

On a Mac the only drafter for verify windows is the MTP layer (plus the suffix drafter). The engine cannot use a DFlash2 draft model; #3322 adds DFlash2 to the CUDA engine, and the Metal engine has nothing.

With this change, `--dflash <draft.gguf>` (opt-in, Metal `--serve`) drafts in place of `--mtp`: up to `--spec - 1` tokens a window from the outputs of target layers 5/15/25/35/45 (the mean of the four hyper-connection streams), and `--spec-min-p` stops a draft where the selector's confidence falls below it. Without `--dflash` the engine runs the same dispatches as before: every new dispatch and buffer is behind a flag only `--dflash` sets.

On an M4 Max (64 GB) with an abliterated IQ3_S target, greedy, at a 42 GB expert arena:

| | MTP (spec 3, min-p 0.7) | DFlash2 fine-tuned for the target (spec 4, min-p 0.75) |
| --- | --- | --- |
| Short prompts, decode tok/s (2 runs) | 48.1, 46.9 | 49.7, 49.7 |
| 29K prompt, cold, decode tok/s (2 runs) | 50.4, 50.0 | 51.0, 51.7 |
| 102K prompt, cold / cached follow-up, decode tok/s (1 run) | 46.8 / 44.4 | 50.5 / 45.1 |

The stock `incoai/Qwen3.8-Flash-Next-DFlash2` drafter was **slower** than MTP on this target (41.1-42.5 vs 42.1-43.7 tok/s short, arena 33). The gain comes from a drafter fine-tuned on the target's own features, not from DFlash2 alone. Greedy output is identical to MTP.

The MTP layer here is not the target's: the abliterated GGUF has no MTP tensors, so (as setup does for it) the MTP arm uses the `mtp.*` block of the official `Qwen/Qwen3.8-Flash-Next` BF16 checkpoint (revision de4b8e4d), packed as `mtp-q2_0.gguf` (experts Q2_0). It was trained with the official model, not this fine-tune, and its experts are Q2_0 against the drafter's Q8_0; both favor DFlash2. This compares what Strata runs for this GGUF today with the fine-tuned drafter, not two drafters made the same way.

arms, same day, M4 Max 64 GB, arena 42 GB, greedy; [bench/results/2026-10-22-metal-dflash2-native](bench/results/2026-10-22-metal-dflash2-native/README.md)):

| | MTP (spec 3, min-p 0.7) | DFlash2 v2 (spec 4, min-p 0.75) |
| --- | --- | --- |
| Short prompts, decode tok/s (2 runs) | 46.9, 46.8 | 50.8, 50.4 (+7.5% to +8.5%) |
| Tokens per window | 1.71 | 2.12 |
| 29K prompt, cold, decode tok/s (2 runs) | 50.2, 49.5 | 52.9, 53.3 |

Greedy output identical to MTP on 6 of 6 prompts (reasoning and answer). The drafter is the incoai checkpoint fine-tuned
on this target (v2, Q8_0); the stock incoai drafter is still not faster than MTP on this abliterated target.

## Approach

- `metal/kernels/gr.metal`: `hc_mean`, one dispatch per captured layer, writes the HC-stream mean of `R` into a feature buffer (5 x n_embd per row). `window.cpp` and `prompt_chain.inc` encode it after the hyper-connection read of layers 5/15/25/35/45 in the decode/verify window, the resident prompt chain and the streaming prompt chunks, only when `df_on_` is set.
- `src/spec/dflash_drafter.cpp`, `include/strata/spec/dflash_*.hpp`: the drafter. Two backends: Strata's own Metal kernels (`metal/kernels/dflash.metal`, `metal/src/engine/dflash.cpp`), the default; and, only in a build with `STRATA_DFLASH_LLAMA`, llama.cpp's DFLASH graph (`libllama` from the pinned llama.cpp 3cf03257, built shared with Metal; `STRATA_DFLASH_NATIVE=0`), the parity reference. The native drafter takes any `token_embd` type the host dequantizer knows and needs the draft-vocabulary head (`tools/dflash_head.py --draft-vocab`, at most 40960 rows); otherwise it refuses with that command. Each prompt chunk and committed window injects its rows' features; a draft runs the block and the selector.
- `src/program/generate.cpp`: `--dflash` parsing and the serve loop's draft source; it refuses `--dflash` with `--mtp` and with `--spec` < 2.
- `STRATA_DFLASH_DUMP=<prefix>` (opt-in, with `--dflash`): appends each committed row's position, token and features to `<prefix>.idx` / `<prefix>.f16`. That is how the training data for the fine-tuned drafter was made; the training script is not in this PR.
- `tools/dflash_head.py`: makes the draft GGUF: a converted DFlash2 draft plus the target's `token_embd` and output head (Q8_0), optionally only the rows of the token ids in the MTP folder's `draft_vocab.bin` (a token-id list, `data/draft_vocab_en.bin` in these runs; no MTP weights) with a `d2t` map. `metal/src/ref_quant.cpp` learns GGUF type 27 (I64) for that map.
- `metal/CMakeLists.txt`: `-DSTRATA_DFLASH=ON` builds `--dflash` with the native drafter only (no llama.cpp build needed). `-DSTRATA_DFLASH_LLAMA=<llama.cpp shared Metal build>` adds the llama.cpp backend and the two test programs. Neither set: nothing new is built and `--dflash` is refused.
- `docs/MAC.md`: a short `--dflash` paragraph. `bench/results/2026-10-20-metal-dflash2/`: the runs.
- The fine-tuned drafter: https://huggingface.co/hotocooo/Qwen3.8-Flash-Next-Abliterated-Uncensored-Turbo-Brilliance-50x-Reasoning-Instruct-GSQ-RCO-DFlash (Apache-2.0, from the incoai checkpoint).

## Limits

- Mac only, and only with `serve/server.py`; setup does not offer it.
- A drafter has to match the target's features: the stock incoai drafter does not pay on this abliterated target. The fine-tuning tools are not part of this PR.
- Few repetitions per cell: differences under about 2 tok/s on short prompts are within the spread between repeats.
