# Add experimental DFlash decoding, setup integration and hardware calibration

## Summary

Adds an experimental standalone DFlash drafter for Qwen3.8-Flash-Next, integrated with Strata's existing target verifier, server and installer.

Setup now offers **MTP**, **DFlash** or **Off**. Selecting DFlash skips MTP download, preparation and loading. Off disables both model drafters while keeping suffix/prompt lookup enabled.

## Changes

- Implement DFlash feature capture, context KV injection and parallel draft generation using the target's embedding and output head.
- Support original BF16 weights and whole-drafter Q8_0, Q5_0 and Q4_0 quantization through llama.cpp's GGML quantizers. Normalization vectors retain their original BF16 values.
- Download and verify the pinned checkpoint, prepare and cache GGUF artifacts, and persist the selected mode in the server configuration.
- Add batched projections, indexed output-head projection, GPU graph reuse and attention over populated KV cells.
- Grow DFlash KV storage and attention scratch as needed on supported CUDA configurations.
- Extend hardware calibration to measure draft widths, confidence thresholds and PCIe settings, with repeated comparisons before saving a configuration.
- Validate artifact metadata, request limits, mask tokens and memory ownership.
- Add loader, setup, quantization, calibration, KV and numerical-reference tests.

Example installation:

```sh
./setup.sh --setup --yes --model IQ3_XXS --drafter dflash --dflash-quant q4
```

## Validation

- CUDA engine build on Linux.
- Setup, calibration, quantization and server tests.
- GPU checks for feature packing, full-head RoPE, owned KV storage and indexed projections.
- Greedy generation tests and stage comparisons against independent references.

## Performance

DFlash does **not yet outperform MTP** in the latest comparison.

Measured on an RTX 4070 Ti SUPER 16 GB, Ryzen 5900X and 128 GB RAM, using the same IQ3_XXS target, eight serial greedy requests and up to 512 generated tokens per request:

| Mode | Aggregate decode throughput |
|---|---:|
| MTP | 83.6 tok/s |
| DFlash | 73.4–76.0 tok/s |

Throughput excludes startup and prefill. These measurements cover short contexts on one machine and do not establish performance across other hardware or workloads. Experimental variants without a confirmed speed benefit were reverted.

## Current limitations

- DFlash drafting supports greedy decoding. Sampled requests fall back to target-only decoding.
- The initial integration supports one GPU and serial requests.
- Target-only conversation snapshots are not reused for DFlash; each request prefills the full prompt.
- `--dflash-window` is a capacity limit, not a rolling attention window.
- HIP and SYCL were not validated in this environment.
