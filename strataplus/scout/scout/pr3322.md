## Problem and result

The official `incoai/Qwen3.8-Flash-Next-DFlash2` checkpoint requires five attention layers with 128-wide heads, raw HC-mean target features, dynamic convolution and a predecessor-conditioned selector. This change implements that checkpoint contract and supports original BF16 weights plus Q8_0, Q5_0 and Q4_0 backbone quantizations, using the full shared target output head. This PR resolves the Qwen3.8-Flash-Next speculative-decoding gap tracked in [issue #3304](https://github.com/Niko1221/Strata/issues/3304) by adding opt-in DFlash2 support and setup integration. The measured results do not establish the suggested 1.5–2× gain across workloads; performance depends on target, prompts, hardware and configuration, as detailed below.

Setup offers MTP (default), experimental DFlash2, or no model drafter. DFlash2 selection enables the local CUDA build, pinned download/conversion and artifact-specific calibration. Weights, private KV pools and attention scratch are accounted for before auto-sizing the expert cache, including the configured context length and elastic growth. MTP and DFlash2 cannot be selected together.

## Related discussion

Explicit maintainer confirmation of the expanded official-checkpoint/setup scope remains pending. This remains a draft while that scope and missing backend validation are resolved.

## Approach

DFlash2 is opt-in behind `STRATA_ENABLE_DFLASH2=ON`. The converter validates the checkpoint geometry and preserves all 45 norm, convolution and selector tensors in BF16; the 36 backbone matrices can be quantized. Setup offers BF16, Q8_0 and Q4_0; Q5_0 is also supported by the converter/runtime and included in the measurements below.

Prompt and conversation snapshots retain the draft context. Cache controls enforce matching actual expert placement before checking output. The shared runtime includes the infrastructure required for proposal verification, a fix for state publication on the opt-in QFUSE path and a fix for the CPU-only loader-test build dependency. The existing default drafter stays MTP.

## Current implementation and speed comparison — measured 2026-10-23

The official DFlash2 path and opt-in runtime optimizations are implemented. **The suggested +32.23% long-prompt decode advantage has not been reached.** The new 256K code run measures +14.84% decode speed over MTP; full request time is 0.72% slower because prompt processing dominates.

## How to enable the pushed optimization options

Use a build containing this PR (implementation `dbaa12db`, evidence follow-up `3aef66c3`) and a compatible DFlash2 artifact. These are **engine environment variables**, not new command-line flags. Set them before starting the engine, then restart the engine after changes; several switches are read only at startup or first use. Selecting MTP does not activate DFlash2-specific kernels.

For a source CUDA build, enable the extension in the normal CUDA configuration:

```bash
cmake -S . -B build-dflash2 -DSTRATA_ENABLE_CUDA=ON -DSTRATA_ENABLE_DFLASH2=ON
cmake --build build-dflash2 --target strata -j4
```

Keep the existing model paths and DFlash2 launch arguments. Set the desired options in the same shell that starts the engine/server; an already-running process does not inherit later shell changes.

| Environment variable | What setting it to 1 enables | Default / important limits |
| --- | --- | --- |
| `STRATA_DFLASH2_SMALL_PAGE_ATTENTION` | Specialized attention indexing and aligned paired FP16 value loads for the runtime's four-cell pages | Off. Official 32Q/8KV geometry; other geometries retain the general path. This is the new kernel option measured in the table. |
| `STRATA_DFLASH2_PROMPT_TAIL` | Skips whole context-fusion batches that future local attention cannot read | Off. Fresh native requests with `--prompt-cache 0`; reference/parity/debug paths keep full processing. Improves prompt processing only, not token acceptance. |
| `STRATA_DFLASH2_PARALLEL_PROJECTIONS` | Runs proposal Q/K/V projections on separate streams, and overlaps gate/up projections | Off. Reference, tensor-dump, debug and section-timing paths retain serial execution. This does not enable the rejected context K/V prototype. |
| `STRATA_DFLASH2_REGISTER_TOPK` | Register-based local candidate top-k within the tiled path | Off. Requires the tiled path and workspace; tiled top-k is already enabled by default. Do not force `STRATA_DFLASH2_SERIAL_TOPK=1` when testing it. |
| `STRATA_DFLASH2_FUSED_CONV` | Fuses convolution epilogues with following conversion/residual work | Off. Reference/parity/debug paths retain their diagnostic behavior. |
| `STRATA_DFLASH2_LATTICE_SELECTOR` | Computes candidate transition scores in parallel before walking the conditioned path | Off. Requires normal selector workspace; serial/reference selector paths bypass it. |
| `STRATA_DFLASH_HEAD_IL` + `STRATA_MMVQ_IL_Q8_HEAD` | Enables DFlash2 interleaved head dispatch and the compatible Q8_0 shared-head kernel | Both off. Set both to 1. The Q8_0 specialization is gated to measured SM89, vocabulary 248320 and supported row counts; unsupported cases retain the existing path. No head weights are replaced. |

For the **small-page-on arm of the speed table**, use the two shared-head options in both MTP and DFlash2 comparisons, and enable only the new small-page option on the DFlash2 arm:

```bash
export STRATA_DFLASH_HEAD_IL=1
export STRATA_MMVQ_IL_Q8_HEAD=1
export STRATA_DFLASH2_SMALL_PAGE_ATTENTION=1
# Start the existing DFlash2 engine command from this shell.
```

Optional, independently testable additions for the existing DFlash2 command:

```bash
export STRATA_DFLASH2_PARALLEL_PROJECTIONS=1
export STRATA_DFLASH2_PROMPT_TAIL=1
# PROMPT_TAIL requires --prompt-cache 0 and the fresh native request path.
# Restart the engine after changing these variables.
```

PowerShell equivalent (syntax reference; Windows execution has not been validated):

```powershell
$env:STRATA_DFLASH_HEAD_IL = "1"
$env:STRATA_MMVQ_IL_Q8_HEAD = "1"
$env:STRATA_DFLASH2_SMALL_PAGE_ATTENTION = "1"
$env:STRATA_DFLASH2_PARALLEL_PROJECTIONS = "1"
$env:STRATA_DFLASH2_PROMPT_TAIL = "1"
# Start/restart the existing DFlash2 engine command from this PowerShell session.
```

The table is **not** a measurement of all options enabled together. Parallel projections, prompt-tail, register top-k, fused convolution and lattice selector are separate experiments; do not infer an additive speedup. To restore these opt-in paths to their defaults, unset the corresponding variables (or set them to 0) and restart. In Bash use `unset STRATA_DFLASH2_PARALLEL_PROJECTIONS`; in PowerShell use `Remove-Item Env:STRATA_DFLASH2_PARALLEL_PROJECTIONS`, and likewise for each enabled option.

The rejected `STRATA_DFLASH2_PARALLEL_CONTEXT`, `STRATA_DFLASH2_WARP_ATTENTION_MAX` and `STRATA_DFLASH2_BF16_STREAM_MEAN` prototypes are **not present in production** and must not be advertised as usable optimization options.

## Prompt-processing and acceptance findings

A separate 7227-token code fixture measures prompt-tail processing at **16897.4 → 16759.0 ms (−0.82%)**, with identical output IDs and 20/28 acceptance. Decode medians are 713.4 and 713.9 ms: no steady-state win. Prompt-time changes on the 2427/2425-token fixtures are negligible. This evidence is separate from the decode-speed table.

The joint diagnostic capture records native BF16 proposals and their exact target features at 95 anchor positions per task. The published BF16 PyTorch drafter, consuming those same features, chooses **the same first proposal at all 285 positions**: 90/95 correct for short code, 81/95 for padded code and 83/95 for cache. Later proposals can differ; this is not full bitwise PyTorch parity or validation of native target features against the upstream teacher. Reference/native correct-prefix sums are 256/258 for padded code and 348/348 for cache. Simply reproducing reference BF16 arithmetic does not recover the missing acceptance on these fixtures.

Context deduplication, two-pass self-conditioning and causal per-request selector feedback did not consistently improve acceptance. Extra context K/V parallelism and warp-maximum reduction did not establish a speed benefit and were removed. Their [patches, results and limitations](https://github.com/j-luwierski/Strata/blob/3aef66c338a662213d07bff9f489c6682279b0ea/bench/results/2026-10-22-dflash2-context-audit/README.md#follow-up-experiments-rejected-after-the-implementation-commit) remain as negative evidence. No weights were fine-tuned in these experiments.

## Latest validation

**Passed:** CUDA builds with DFlash2 enabled and disabled; `dflash_load_test`, `dflash_policy_test`; default/enabled `dflash2_parity --bench`; 30 before/default/enabled attention outputs bit-identical, including four-cell pages, unaligned fallback and physical rings; independent FP64 attention oracle; long NumPy stage oracle for all five layers/live KV/final normalization/selector within documented tolerances; fresh native output controls, complete joint feature/proposal capture and Python syntax compilation of the modified stage oracle.

Diagnostic prototypes were removed and production rebuilt. SHA256 `42a56c9a217ddb47c58fa6f42ad331c77ae2c296a532d84c53b3610fedb4a3f2` matches the executable used for the latest table.

**Failed / rejected:** the follow-up algorithm and scheduling experiments did not meet their acceptance/performance goals. Initial incomplete captures were retained and excluded from final findings. Earlier test failures remain documented below and in their original reports.

**Not run on the latest head:** HIP/SYCL compilation/execution (compilers unavailable), Metal, Windows, other target families, multi-GPU, vision, concurrent requests, a held-out long-prompt suite or full 128K prompt sweep. Earlier validation at another revision is not claimed as a latest-head rerun. This PR remains a draft pending scope agreement and missing backend validation.

## Limits

Sampled DFlash2 requests use target-only fallback. Cache equality checks cover tested arithmetic paths and matching placement, not every configuration. Disk session restoration is unsupported. The CUDA extension is restricted to one GPU and serial requests. The latest table uses equal actual expert placement; older auto-cache reports allowed different placement, so their results must not be mixed. Performance conclusions apply to the measured hardware and prompts. No universal speedup or +32% long-prompt result is claimed.

This fine-tune was trained for DavidAU's Turbo-Brilliance GSQ-RCO IQ3_S target. Setup downloads its BF16 `model.safetensors`, converts it to GGUF and keeps it in a separate cache. The CUDA DFlash2 conversion of this fine-tune has not been performance-benchmarked; the upstream Apple M4 timings are for the separate plain-DFlash GGUF.
